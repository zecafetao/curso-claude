# 2.7 E-mail e landing page em HTML

**Carga:** 3 h (1 h de leitura, 2 h de exercício)

## Objetivo

Produzir com o Claude o HTML de um e-mail que funciona nos programas de e-mail e uma landing page pronta para publicar, e corrigir problemas de aparência a partir de prints.

## Por que importa no seu trabalho

E-mails e landing pages em HTML são entregas suas de toda campanha. O Claude escreve os dois em minutos, mas as duas peças seguem regras opostas, e a maior parte dos problemas vem de tratar uma como a outra. Um e-mail escrito como página web quebra no Outlook. Uma landing page escrita como e-mail fica presa a técnicas de vinte anos atrás. Este módulo ensina as regras de cada uma, como pedir e, principalmente, como testar.

## Conteúdo

### 1. E-mail não é página web

Uma página web é aberta em um navegador moderno. Um e-mail é aberto em dezenas de programas, cada um com as próprias limitações:

| Programa | Comportamento que quebra e-mails |
| --- | --- |
| Outlook para Windows | Usa o motor do Word para exibir. Ignora boa parte do CSS moderno |
| Gmail | Remove ou reescreve parte dos estilos |
| Vários programas | Bloqueiam imagens até o leitor autorizar |
| Modo escuro | Inverte ou ajusta cores por conta própria |
| Celular | Tela de 360 a 400 pixels de largura |

A consequência é um conjunto de regras conservadoras. Elas parecem antiquadas e são o que funciona.

### 2. As regras do HTML de e-mail

| Regra | Por quê |
| --- | --- |
| Layout em tabelas | É a única estrutura que todos os programas respeitam |
| Estilos embutidos em cada elemento | Folhas de estilo e blocos de estilo são removidos por alguns programas |
| Largura máxima de 600 pixels, fluida em telas menores | Cabe no painel de leitura e no celular |
| Fontes do sistema, como Arial | Fontes da web não carregam em vários programas |
| Texto de verdade, não texto dentro de imagem | Com imagens bloqueadas, o leitor ainda lê a mensagem |
| Botão feito de célula colorida com link | Aparece mesmo com imagens bloqueadas |
| Toda imagem com largura definida e texto alternativo | O texto alternativo é o que se vê quando a imagem não carrega |
| Links completos, com `https://` | Links relativos não funcionam fora do site |
| Sem JavaScript, formulário ou vídeo | São removidos ou bloqueados |
| Pré-cabeçalho oculto no início do corpo | É o texto que aparece ao lado do assunto na caixa de entrada |
| Versão só de texto junto com o HTML | Melhora a entrega e atende quem lê sem HTML |
| Rodapé com descadastro, remetente e motivo do recebimento | É exigência de boas práticas e de transparência com o destinatário |

O arquivo [`dados/email_referencia.html`](dados/email_referencia.html) aplica todas essas regras ao convite da Expo Modelo, e o [`dados/email_referencia.txt`](dados/email_referencia.txt) é a versão de texto. Abra o HTML no navegador e no VS Code, lado a lado, para ver como cada parte do código vira uma parte do e-mail.

### 3. Contraste e legibilidade

O botão do briefing é laranja. O texto do botão parece pedir branco, e essa é a escolha errada: branco sobre esse laranja tem contraste de 2,4 para 1, abaixo do mínimo recomendado de 4,5 para 1 para texto. O e-mail de referência usa texto escuro, com contraste de 6,8 para 1.

Regras práticas:

- texto do corpo com pelo menos 14 pixels, de preferência 16;
- contraste de pelo menos 4,5 para 1 entre texto e fundo;
- botão com altura suficiente para o dedo: cerca de 44 pixels;
- uma mensagem e um botão por e-mail, como manda o guia de tom.

Você pode pedir ao Claude: "calcule o contraste entre a cor do texto e a cor do fundo de cada bloco e aponte os que ficam abaixo de 4,5 para 1".

### 4. Como pedir o HTML de um e-mail

O texto vem antes do código. Aprove o conteúdo (módulo 2.1) e só então peça o HTML. Um pedido completo tem:

1. **O conteúdo aprovado:** assunto, pré-cabeçalho, corpo e texto do botão.
2. **As regras:** o guia de tom, com a seção de HTML.
3. **A identidade visual:** cores e fonte do briefing.
4. **A ferramenta de disparo:** para que as variáveis de personalização saiam na sintaxe certa.
5. **A forma da entrega:** o HTML em um arquivo, a versão de texto e uma explicação curta de cada bloco.

Exemplo:

> Gere o HTML do e-mail abaixo, seguindo as regras de HTML do guia de tom e a identidade visual do briefing. O e-mail será disparado por [nome da ferramenta]; use a sintaxe dela para o link de descadastro e para o primeiro nome do destinatário, com "visitante" como valor padrão quando o nome não existir.
>
> Entregue o HTML em um arquivo, a versão só de texto em outro e uma lista do que cada bloco do código faz. Depois, confira o resultado contra a lista de regras e informe qualquer regra que não foi cumprida.
>
> [conteúdo aprovado]

Pedir a conferência contra as regras no fim do pedido faz o Claude reler o próprio código. Não substitui o seu teste.

**Sobre personalização:** as variáveis ficam como marcadores no HTML. Dados reais de destinatários não entram na conversa. Teste com um contato fictício na ferramenta de disparo.

### 5. Testar e corrigir com prints

O navegador mostra o e-mail como um navegador. O teste que vale é o envio real.

Ciclo de teste:

1. Envie o e-mail de teste para você mesmo pela ferramenta de disparo.
2. Abra nos programas que o seu público usa: Outlook, Gmail, o aplicativo do celular. Abra também no modo escuro e com as imagens bloqueadas.
3. Para cada problema, tire um print.
4. Envie ao Claude o print, o nome do programa e o trecho do HTML: "No Outlook para Windows, o botão perdeu o fundo laranja, como mostra o print. Corrija só o botão, sem alterar o restante."
5. Aplique a correção, envie de novo e confira. Uma correção por vez.

O print é o que permite ao Claude ver o problema (módulo 1.3). Sem ele, a descrição "ficou estranho no Outlook" não dá o que corrigir.

Antes de enviar um print, confira se ele não mostra a sua caixa de entrada, com remetentes e assuntos de outras mensagens.

### 6. Landing page: as regras mudam

A landing page é aberta em navegadores modernos. Aqui valem as técnicas atuais: layout flexível, fontes da web, formulários.

Uma landing page de campanha tem uma única função: levar o visitante a uma ação. A estrutura:

| Bloco | Conteúdo |
| --- | --- |
| Topo | A promessa em uma frase, a data e o local, e o botão |
| Argumentos | Três motivos, no máximo |
| Prova | Números da edição, marcas presentes, programação resumida |
| Formulário | Só os campos necessários |
| Rodapé | Organizador, contato e política de privacidade |

O que conferir em toda landing page:

- **Funciona no celular.** A maior parte dos cliques de e-mail chega pelo celular.
- **O formulário pede o mínimo.** Cada campo a mais reduz a conversão.
- **O consentimento é explícito.** Uma caixa de seleção desmarcada, com o texto do que a pessoa aceita e o link da política de privacidade. É o registro que o layout de importação do CRM exige: consentimento e data.
- **Os campos têm rótulo.** Leitores de tela dependem deles.
- **A página carrega rápido.** Imagens leves, sem recursos desnecessários.
- **O título e a descrição da página estão preenchidos.** É o que aparece ao compartilhar o link.

### 7. O que o HTML sozinho não faz

Dois pontos em que uma página gerada parece pronta e não está:

- **O formulário não grava nada.** O HTML desenha os campos. Para os dados chegarem ao CRM, o formulário precisa ser ligado ao formulário do CRM ou a um serviço de captura. Peça ao Claude que deixe o destino do formulário marcado com um comentário e explique como ligar ao seu CRM. A ligação em si é feita na sua ferramenta.
- **A origem do visitante precisa ser medida.** Os links dos e-mails devem carregar parâmetros de campanha, conhecidos como UTM, para que a página e o CRM saibam de onde veio cada visita:

```
https://expomodelo.example/credenciamento?utm_source=email&utm_medium=crm&utm_campaign=credenciamento_out26&utm_content=convite_direto
```

| Parâmetro | Informa |
| --- | --- |
| `utm_source` | De onde veio: `email`, `whatsapp` |
| `utm_medium` | O tipo de canal |
| `utm_campaign` | A campanha |
| `utm_content` | A peça: qual e-mail, qual versão |

É o que torna possível a análise de origem que você faz nos relatórios. Defina um padrão de nomes e peça ao Claude que monte os links de todos os disparos seguindo esse padrão.

### 8. Landing page com o Claude Design

O modelo de **Design** dos Artifacts (módulo 1.3) é o caminho mais direto para uma landing page. Referência: novembro de 2026; detalhes na [ajuda do Claude Design](https://support.claude.com/en/articles/14604416-get-started-with-claude-design).

Como usar:

1. Em uma conversa, escolha o tipo de saída (*Output*) e depois *Design*, ou peça uma landing page.
2. Dê o contexto: o briefing, a identidade visual, prints de páginas que servem de referência.
3. Descreva o que quer e revise o resultado na tela.
4. Ajuste de três formas, conforme o tamanho da mudança:

| Forma | Use para |
| --- | --- |
| Conversa | Mudanças de estrutura: "inverta a ordem dos argumentos e do formulário" |
| Comentário em um ponto da tela | Mudanças em um componente: "este título está longo" |
| Edição direta | Ajustes visuais: arrastar, redimensionar, alinhar |

5. Exporte pelo botão de exportar: HTML independente, PDF, PowerPoint ou arquivo compactado. Há também envio direto para algumas ferramentas de marketing e de publicação de sites.

**Sistema de design.** Em planos pagos, você pode ensinar a identidade da marca uma vez: peça ao Claude que monte um sistema de design a partir de logotipos, apresentações e materiais da marca. Ele extrai cores, tipografia, componentes e padrões de layout, e os designs seguintes já nascem nesse padrão. O recurso está em fase beta. Detalhes na [ajuda sobre sistemas de design](https://support.claude.com/en/articles/14604397-set-up-your-design-system-in-claude-design).

Limites informados na documentação: ainda não há histórico de versões, e a edição simultânea por várias pessoas é básica. Antes de uma mudança grande, peça ao Claude que salve o estado atual.

O Claude Design serve para a landing page e para peças visuais. O e-mail em HTML continua sendo código com as regras da seção 2: peça como código, não como design.

### 9. Antes de publicar ou disparar

Esta é uma das conferências obrigatórias do módulo 2.9. O Claude pode ajudar com a lista; a aprovação é sua.

## Exemplo aplicado

O Outlook exibiu o botão sem cor de fundo. A conversa de correção:

> **Você:** [print do e-mail no Outlook] No Outlook para Windows, o botão aparece só como texto sublinhado, sem o fundo laranja. Este é o trecho do botão: [trecho do HTML]. Corrija só esse trecho.
>
> **Claude:** explica que o fundo estava aplicado ao link e que o Outlook ignora fundo e espaçamento em links; propõe aplicar a cor à célula da tabela que contém o link, e devolve o trecho corrigido.
>
> **Você:** aplica, reenvia o teste e confere no Outlook e no Gmail, para garantir que a correção não quebrou o outro.

Três coisas tornaram a correção rápida: o print, o nome do programa e o pedido restrito a um trecho. É a mesma correção já presente no e-mail de referência, em que a cor está na célula.

## Exercício

**Tempo:** 2 h

### Parte A — E-mail (1 h 10)

1. No Project "Redator de e-mail — Expo Modelo" do módulo 2.1, use o convite aprovado no exercício de lá. Se não tiver, peça o texto antes.

4. Confira o seu e-mail contra a lista abaixo. Para cada item reprovado, peça a correção, um item por vez.
5. Se você tiver acesso a uma ferramenta de disparo, envie um teste para você e abra em dois programas. Tire um print de um problema e faça o ciclo da seção 5. Se não tiver, simule: tire um print do e-mail na largura de celular e peça ao Claude que aponte problemas de leitura.
6. Compare o seu HTML com o [`dados/email_referencia.html`](dados/email_referencia.html). Anote duas diferenças e decida qual versão está melhor em cada uma.

| # | Item | Como conferir |

| 10 | Contraste do texto do botão de pelo menos 4,5 para 1 | Pedir o cálculo ao Claude |

| 12 | Sem exclamações, superlativos ou emojis | Ler |

O e-mail de referência cumpre os 15 itens. Os itens 1, 2, 3, 5, 6, 7, 9, 10, 11, 12 e 14 foram verificados por código e por renderização nas duas larguras.

### Parte B — Landing page (50 min)

7. Crie a landing page do briefing com o modelo de design, ou peça o HTML em uma conversa se o modelo não estiver disponível no seu plano.
8. Inclua o formulário com os quatro campos do briefing e a caixa de consentimento, desmarcada, com o texto do aceite.
9. Peça os links dos três e-mails da campanha (convite, lembrete e última chamada) com os parâmetros de campanha, em um padrão de nomes definido por você.
10. Exporte como HTML independente e abra no computador e no celular.
11. Confira contra a lista da seção 6 e contra o briefing.
12. Peça ao Claude a explicação de como ligar o formulário ao seu CRM e anote o que precisa ser feito na ferramenta.

**Entregável:** o HTML e a versão de texto do e-mail, a lista de 15 itens preenchida, o HTML da landing page, os três links com parâmetros de campanha e a anotação sobre o formulário.

**Critério de conclusão:**

- O e-mail cumpre os 15 itens.
- A landing page funciona no celular, segue o briefing e tem o consentimento explícito.
- Os três links seguem o mesmo padrão de nomes.
- Você sabe dizer o que falta para o formulário gravar dados.

## Erros comuns

- Pedir o e-mail como se fosse uma página web e descobrir o problema no Outlook.
- Aprovar o e-mail olhando só o navegador.
- Pôr o texto principal dentro de uma imagem.
- Usar texto branco sobre um botão claro.
- Descrever um problema de aparência sem enviar o print.
- Pedir várias correções de uma vez e não saber qual quebrou o quê.
- Publicar uma landing page cujo formulário não grava em lugar nenhum.
- Disparar sem parâmetros de campanha e não conseguir medir a origem depois.
- Colar dados reais de destinatários para "testar a personalização".
