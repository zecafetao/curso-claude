# 3.2 Entradas multimodais

**Carga:** 3 h (1 h de leitura e experimentação, 2 h de exercício)

## Objetivo

Enviar PDFs e imagens pela API, receber respostas que indicam a página de cada afirmação e conferir essas respostas contra o documento.

## Por que importa no seu trabalho

Os seus estudos de mercado partem de relatórios em PDF. Os relatórios de campanha partem de gráficos e prints do CRM. No app, você anexa o arquivo e pergunta. Pela API, o script faz o mesmo para dez relatórios em sequência e guarda, ao lado de cada número, a página de onde ele saiu. É a página que permite a conferência exigida no módulo 1.5: abrir o documento e ver o número.

**Multimodal** significa que a entrada combina mais de um tipo de conteúdo: texto, imagem e documento.

## Conteúdo

### 1. O conteúdo de uma mensagem é uma lista de blocos

No módulo 3.1, o conteúdo de cada mensagem era um texto. Essa é a forma abreviada. Na forma completa, o conteúdo é uma lista de blocos, e cada bloco tem um tipo:

| Tipo | O que leva |
| --- | --- |
| `text` | Texto |
| `image` | Uma imagem |
| `document` | Um documento, como um PDF |

As duas mensagens abaixo são equivalentes:

```python
mensagem_curta = {"role": "user", "content": "O que é taxa de clique?"}

mensagem_completa = {"role": "user", "content": [{"type": "text", "text": "O que é taxa de clique?"}]}
```

Para enviar um arquivo com uma pergunta, a lista leva dois blocos: primeiro o arquivo, depois o texto.

Os trechos das seções 2 a 6 continuam um ao outro. Escreva-os em um arquivo `testar_arquivos.py`.

### 2. Imagens

Um arquivo de imagem é uma sequência de bytes, e uma requisição em JSON só leva texto. A ponte entre os dois é o **base64**, uma forma de escrever qualquer arquivo usando só letras, números e alguns símbolos. A biblioteca `base64` do Python faz a conversão.

```python
import base64
from pathlib import Path

import claude_util as cu


def bloco_imagem(caminho):
    """Monta o bloco de uma imagem PNG enviada dentro da requisição."""
    dados = base64.standard_b64encode(Path(caminho).read_bytes()).decode("utf-8")
    return {"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": dados}}


cliente = cu.criar_cliente()
pedido = (
    "Transcreva os valores deste gráfico em uma tabela com as colunas público e taxa de clique. "
    "Copie os números como aparecem. Se algum valor não estiver legível, escreva 'ilegível'."
)
mensagens = [{"role": "user", "content": [
    bloco_imagem("dados_n3/grafico_clique_por_publico.png"),
    {"type": "text", "text": pedido},
]}]

resposta = cu.chamar(cliente, mensagens, esforco="low")
print(cu.texto_da_resposta(resposta))
print(resposta.usage.input_tokens)
```

`media_type` informa o formato: `image/png`, `image/jpeg`, `image/gif` ou `image/webp`.

**Custo.** A imagem é cobrada como tokens de entrada, e a quantidade cresce com o tamanho em pixels, não com o tamanho do arquivo em disco. Cada quadrado de 28 × 28 pixels vira um token. O gráfico do exercício tem 1.600 × 840 pixels: são 58 × 30 quadrados, cerca de 1.740 tokens. Imagens muito grandes são reduzidas pelo serviço antes da contagem. Um print de tela inteira custa bem mais que um recorte do gráfico: recorte a imagem para o que a tarefa precisa e confira o consumo no `usage`. O limite é de 10 MB por imagem (documentação oficial, novembro de 2026).

**Limites da leitura.** Valem os cuidados do módulo 1.3. O modelo lê bem títulos, rótulos e valores escritos no gráfico. Valores que dependem de estimar a altura de uma barra sem rótulo são aproximações. Por isso o pedido acima diz para copiar os números como aparecem e marcar o que não estiver legível. Todo número lido de imagem é conferido antes de entrar em um relatório.

### 3. PDFs

O PDF vai em um bloco `document`, também em base64.

```python
def bloco_pdf(caminho, titulo):
    """Monta o bloco de um PDF enviado dentro da requisição, com citações ligadas."""
    dados = base64.standard_b64encode(Path(caminho).read_bytes()).decode("utf-8")
    return {
        "type": "document",
        "source": {"type": "base64", "media_type": "application/pdf", "data": dados},
        "title": titulo,
        "citations": {"enabled": True},
    }


pdf = bloco_pdf("dados_n3/relatorio_mercado_embalagens.pdf", "Mercado de Embalagens no Brasil")
```

| Chave | O que é |
| --- | --- |
| `source` | O arquivo: o tipo de envio, o formato e os dados |
| `title` | Opcional. O nome que o modelo usa para se referir ao documento |
| `citations` | Opcional. Liga as citações, explicadas na seção 4 |

O que acontece do outro lado: cada página do PDF é convertida em uma imagem, e o texto da página é extraído e enviado junto. O modelo recebe os dois. É por isso que ele lê tabelas e gráficos que estão dentro do PDF, e não só o texto corrido.

Números de referência (documentação oficial, novembro de 2026):

| Item | Valor |
| --- | --- |
| Custo do texto | De 1.500 a 3.000 tokens por página, conforme a densidade, mais o custo da imagem de cada página |
| Páginas por requisição | Até 600 |
| Tamanho da requisição | Até 128 MB |
| Restrição | PDF comum, sem senha |

Um relatório de 40 páginas pode passar de 100 mil tokens de entrada por pergunta. Com o Opus 5.5, são cerca de 40 centavos de dólar a cada pergunta, porque a API não guarda a conversa e o documento é reenviado toda vez. O módulo 3.5 mostra como o cache reduz esse custo quando há várias perguntas sobre o mesmo documento.

### 4. Perguntar e receber as páginas

O documento vem antes da pergunta, como você já fazia no app (módulo 2.3).

```python
SISTEMA = (
    "Responda só com base no documento fornecido e cite os trechos que sustentam cada afirmação. "
    "Se a informação não estiver no documento, diga que ela não consta. Respostas curtas."
)

mensagens = [{"role": "user", "content": [
    pdf,
    {"type": "text", "text": "Qual foi o valor bruto da produção em 2025?"},
]}]
resposta = cu.chamar(cliente, mensagens, sistema=SISTEMA, esforco="low")

for bloco in resposta.content:
    if bloco.type == "text":
        print(repr(bloco.text))
        for citacao in bloco.citations or []:
            print(f"    página {citacao.start_page_number}: {citacao.cited_text[:70]!r}")
```

Com as **citações** ligadas, a resposta chega dividida em vários blocos de texto. Cada bloco traz uma afirmação e, quando ela vem do documento, a lista de trechos que a sustentam. Um bloco sem citação é texto do próprio modelo: uma ligação entre frases ou uma conclusão.

Cada citação de um PDF traz:

| Campo | O que é |
| --- | --- |
| `cited_text` | O trecho literal do documento |
| `document_title` | O título informado no bloco do documento |
| `start_page_number` | A página em que o trecho começa. A primeira página é a 1 |
| `end_page_number` | A página seguinte à última do trecho. Um trecho que está só na página 2 vem com início 2 e fim 3 |

Três regras das citações:

- O `cited_text` não é cobrado como saída. A citação sai mais barata do que pedir ao modelo que transcreva os trechos.
- Se a requisição tiver mais de um documento, as citações ficam ligadas em todos ou em nenhum.
- Citações não podem ser combinadas com a saída estruturada do módulo 3.3. A API recusa a requisição.

Pedir os trechos antes da resposta era uma técnica de prompt no módulo 2.3. Aqui ela vira um recurso da API: o trecho citado é copiado do documento pelo sistema, e não redigido pelo modelo. O que continua sendo trabalho seu é ler o trecho e conferir se ele sustenta a afirmação.

### 5. Juntar o texto e as páginas

Para gravar a resposta em uma planilha, o script precisa do texto inteiro e da lista de páginas citadas.

```python
def texto_e_paginas(resposta):
    """Devolve (texto, lista ordenada das páginas citadas) de uma resposta com citações."""
    partes, paginas = [], set()
    for bloco in resposta.content:
        if bloco.type != "text":
            continue
        partes.append(bloco.text)
        for citacao in bloco.citations or []:
            if citacao.type == "page_location":
                fim = max(citacao.end_page_number, citacao.start_page_number + 1)
                paginas.update(range(citacao.start_page_number, fim))
    return "".join(partes), sorted(paginas)


texto, paginas = texto_e_paginas(resposta)
print(texto)
print(paginas)
```

O `max` da função é uma proteção: garante que ao menos a página inicial entra na lista, qualquer que seja o valor do fim.

Uma resposta sem nenhuma página citada é um sinal. Ou a informação não consta no documento e o modelo disse isso, ou o modelo respondeu sem apoio no documento. Nos dois casos, o script deve marcar a linha para revisão.

### 6. Enviar o arquivo uma vez: a Files API

Em base64, o PDF viaja inteiro em cada requisição. A **Files API** guarda o arquivo na Anthropic e devolve um identificador, que você usa nas requisições seguintes.

```python
arquivo = cliente.files.upload(file=Path("dados_n3/relatorio_mercado_embalagens.pdf"))
print(arquivo.id)

pdf_enviado = {
    "type": "document",
    "source": {"type": "file", "file_id": arquivo.id},
    "title": "Mercado de Embalagens no Brasil",
    "citations": {"enabled": True},
}
mensagens = [{"role": "user", "content": [
    pdf_enviado,
    {"type": "text", "text": "Qual é o principal setor cliente da indústria de embalagens?"},
]}]
resposta = cu.chamar(cliente, mensagens, sistema=SISTEMA, esforco="low")
print(texto_e_paginas(resposta))

cliente.files.delete(arquivo.id)          # apague quando terminar
```

| | Base64 | Files API |
| --- | --- | --- |
| O arquivo viaja | Em toda requisição | Uma vez |
| Tokens cobrados por pergunta | Os do documento | Os mesmos |
| Onde o arquivo fica | Só no seu computador | Guardado na Anthropic até você apagar |
| Indicado para | Poucas perguntas, arquivos pequenos | Muitas perguntas sobre o mesmo arquivo, arquivos grandes |

A Files API economiza tempo de envio, e não tokens. As operações de envio e de exclusão são gratuitas. O limite é de 500 MB por arquivo (documentação oficial, novembro de 2026).

O arquivo enviado permanece guardado até ser apagado, e qualquer chave da mesma área de trabalho do Console consegue usá-lo. Para um relatório público, isso é indiferente. Para um documento de cliente, é uma cópia a mais fora do seu computador: siga a política da empresa e apague ao terminar, como faz a última linha do trecho.

## Exemplo aplicado

**Situação.** Você prepara o estudo de mercado de uma feira de embalagens e recebeu um relatório setorial em PDF. Precisa de seis números para o estudo, cada um com a página, porque o estudo vai para o cliente com as fontes.

**Decisões.**

1. Uma pergunta por chamada. A resposta fica curta e as citações ficam ligadas a um único fato.
2. As instruções de sistema limitam a resposta ao documento e pedem que a ausência seja declarada.
3. O script grava pergunta, resposta e páginas em um CSV. A conferência é feita depois, com o PDF aberto.
4. O esforço fica em `low`: localizar um número em seis páginas não exige raciocínio longo.

**Um resultado e a conferência.** Para a pergunta "O valor da produção inclui os fabricantes de máquinas?", a resposta esperada combina duas páginas: o valor de R$ 148,0 bilhões está na página 2, e a informação de que máquinas e equipamentos ficam fora do cálculo, com a estimativa de R$ 152 bilhões quando incluídos, está na página 6. Se a resposta citar só a página 2, falta a ressalva. Se disser que inclui, está errada, e a página citada permite ver isso em segundos.

**O que isso muda no estudo.** O número que vai para o cliente é acompanhado do escopo: "R$ 148,0 bilhões, sem máquinas e equipamentos (p. 2 e 6)". Sem a página 6, o estudo compararia esse valor com fontes que incluem máquinas.

A solução completa está em [`gabarito/perguntar_pdf.py`](gabarito/perguntar_pdf.py).

## Erros comuns

- Colocar a pergunta antes do documento.
- Usar o número da resposta sem abrir a página citada.
- Tratar uma resposta sem citação como se fosse apoiada no documento.
- Enviar um print de tela inteira quando só o gráfico interessa, e pagar pelos pixels que sobram.
- Confiar em valores estimados pela altura das barras de um gráfico sem rótulos.
- Esquecer que cada pergunta reenvia e cobra o documento inteiro.
- Deixar arquivos guardados na Files API depois do trabalho.
- Ler `end_page_number` como a última página do trecho. Ele aponta para a página seguinte.

## Checagem rápida

1. Por que o modelo consegue ler uma tabela que está dentro de um PDF?
2. Uma citação veio com `start_page_number` 4 e `end_page_number` 5. Em que página está o trecho?
3. O que a Files API economiza, e o que ela não economiza?
4. A resposta a uma pergunta veio sem nenhuma citação. O que o script deve fazer com ela?
5. Um PDF de 30 páginas consome cerca de 75 mil tokens de entrada. Quanto custam 20 perguntas no Opus 5.5, contando só a entrada?

<details>
<summary>Respostas</summary>

1. Porque cada página é enviada como imagem, junto com o texto extraído. O modelo recebe a aparência da página, e não só o texto corrido.
2. Na página 4. O fim aponta para a página seguinte à última do trecho.
3. Economiza o envio repetido do arquivo, que passa a viajar uma vez. Não economiza tokens: o conteúdo do documento é cobrado em cada pergunta.
4. Marcar para revisão. Ou a informação não consta e o modelo disse isso, ou a resposta não se apoia no documento.
5. `20 × 75.000 × 4 / 1.000.000` = 6 dólares.

</details>
