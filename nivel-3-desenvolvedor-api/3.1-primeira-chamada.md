# 3.1 Primeira chamada

**Carga:** 3 h (1 h 15 de leitura e experimentação, 1 h 45 de exercício)

## Objetivo

Chamar o Claude de dentro de um script em Python, entender cada parte da requisição e da resposta, manter uma conversa com histórico e calcular o custo de cada chamada.

## Por que importa no seu trabalho

No app, você é a ponte entre a base e o Claude: abre o arquivo, cola, pede, copia a resposta. Isso funciona para uma base. Não funciona para o relatório que sai todo mês nem para a base de 20 mil linhas que precisa de uma classificação por linha.

Pela API, o seu script faz esse papel. Ele decide o que enviar, lê a resposta, confere e grava. O que você ganha: repetição sem trabalho manual, controle exato do que sai do computador e o custo de cada operação em números.

## Conteúdo

### 1. App e API: o que muda

A **API** do Claude é o mesmo tipo de serviço que você usou no módulo P.4: uma requisição, uma resposta em JSON, uma chave de acesso. A diferença para o app está no que vem pronto.

| | App (claude.ai) | API |
| --- | --- | --- |
| Quem usa | Você, pela tela | O seu script |
| Cobrança | Assinatura mensal | Por token, com créditos, em uma conta separada |
| Memória da conversa | O app guarda | Não existe: o script envia o histórico a cada chamada |
| Projects, Skills, Artifacts | Prontos | Não existem: o script monta as instruções e trata os arquivos |
| Arquivos | Anexar na tela | O script lê e envia o conteúdo |
| Limite | Limite de uso do plano | Limite de gasto que você define |

A API é cobrada à parte da assinatura do app, em uma conta do Claude Console, e os créditos da API não valem no app.

Há uma exceção parcial (documentação oficial, novembro de 2026): os planos Max, Ultra e Team incluem créditos mensais de API. O plano gratuito, o Pro e o Enterprise não incluem.

| Plano | Créditos mensais de API |
| --- | --- |
| Max | 100 dólares |
| Ultra | 200 dólares |
| Team | 20 dólares por assento Standard e 100 por assento Premium, somados para a organização, até 500 dólares |

Esses créditos precisam ser ativados, não acumulam de um mês para o outro e são gastos antes dos créditos comprados. Valem para a API e para a área de testes do Console. Não valem para o Claude Code nem para uso extra no app. Assinantes novos esperam 7 dias para ativar.

### 2. Conta, créditos e chave

O **Claude Console** é o site em que você administra o uso da API: [platform.claude.com](https://platform.claude.com/). Os nomes de menu abaixo são de novembro de 2026 e podem mudar.

1. Crie a conta no Console. Pode ser com o mesmo e-mail do app.
2. Obtenha créditos, de uma destas formas:
   - **Plano Max, Ultra ou Team.** Ative os créditos mensais. No app, abra **Settings > Billing** (no Team, **Organization settings > Billing**, com um perfil de proprietário), vá à seção **API credits**, escolha a organização do Console e aceite os termos. Os créditos aparecem na página de cobrança do Console como créditos promocionais.
   - **Demais planos.** Compre créditos em [platform.claude.com/settings/billing](https://platform.claude.com/settings/billing), no botão **Buy credits**. Escolha um valor baixo: o nível inteiro consome poucos dólares. Créditos comprados valem por um ano e não são reembolsáveis. Deixe a recarga automática desligada durante o curso.
3. Defina um limite de gasto mensal em [platform.claude.com/settings/spend-limits](https://platform.claude.com/settings/spend-limits). Um valor de 10 dólares cobre o nível. Com o limite, um erro de programação que dispare chamadas em excesso para de gastar ao atingir o valor.
4. Crie uma chave em [platform.claude.com/settings/keys](https://platform.claude.com/settings/keys). Dê um nome que identifique o uso, como `curso-nivel-3`. A chave aparece uma única vez: copie na hora.

A **chave de API** identifica a sua conta em cada requisição. Quem tiver a chave gasta os seus créditos. Três regras:

- A chave nunca aparece no código nem entra no Git.
- A chave fica em uma **variável de ambiente**, um valor guardado pelo sistema operacional que os programas conseguem ler.
- Se a chave vazar (foi colada em um chat, entrou em um commit), apague-a no Console e crie outra. Não há como "esconder de novo".

Para gravar a variável de ambiente:

**macOS.** Acrescente esta linha ao fim do arquivo `~/.zshrc` e abra um terminal novo:


Para conferir sem mostrar a chave na tela:

### 4. A primeira chamada

```python
import anthropic

MODELO = "claude-opus-5-5"

cliente = anthropic.Anthropic()      # lê a chave da variável de ambiente ANTHROPIC_API_KEY

resposta = cliente.messages.create(
    model=MODELO,
    max_tokens=16000,
    messages=[{"role": "user", "content": "Em uma frase: o que é taxa de abertura de e-mail?"}],
)

for bloco in resposta.content:
    if bloco.type == "text":
        print(bloco.text)
```

Três parâmetros são obrigatórios:

| Parâmetro | O que é |
| --- | --- |
| `model` | O identificador do modelo. O curso usa `claude-opus-5-5`. O texto precisa ser exato |
| `max_tokens` | O máximo de tokens que a resposta pode ter, com o raciocínio incluído. Você paga pelos tokens gerados, não pelo limite |
| `messages` | A conversa: uma lista de mensagens, cada uma com o papel (`role`) e o conteúdo (`content`) |

O papel `user` é o seu lado da conversa. O papel `assistant` é o lado do Claude.

Sobre o `max_tokens`: 16.000 é um valor seguro para chamadas comuns. Um limite baixo demais corta a resposta no meio, como você verá na seção 8.

Identificadores e preços dos modelos em novembro de 2026, em dólares por milhão de tokens:

| Modelo | Identificador | Entrada | Saída |
| --- | --- | --- | --- |
| Claude Opus 5.5 | `claude-opus-5-5` | 4,00 | 20,00 |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | 2,00 | 10,00 |
| Claude Haiku 5.5 | `claude-haiku-5-5` | 0,10 | 0,50 |

O curso usa o Opus 5.5, que é o modelo padrão recomendado na documentação. O caminho para gastar menos é medir primeiro o acerto com ele e depois testar um modelo menor contra o mesmo gabarito. O módulo 3.5 faz isso. Confira a [página de preços](https://platform.claude.com/docs/en/about-claude/pricing) antes de usar esses números em um orçamento.

### 5. Anatomia da resposta

A resposta é um objeto com mais do que o texto.

```python
print(resposta.id)                                   # identificador da resposta
print(resposta.model)                                # o modelo que respondeu
print(resposta.stop_reason)                          # por que a geração parou
print([bloco.type for bloco in resposta.content])    # os tipos de bloco do conteúdo
print(resposta.usage.input_tokens)                   # tokens de entrada cobrados
print(resposta.usage.output_tokens)                  # tokens de saída cobrados
```

| Campo | O que traz |
| --- | --- |
| `content` | Uma lista de **blocos**. O texto da resposta está nos blocos de tipo `text` |
| `stop_reason` | O motivo da parada. `end_turn` significa que o modelo terminou a resposta |
| `usage` | Os tokens consumidos. É a base do cálculo de custo |

O conteúdo é uma lista porque uma resposta pode ter partes de tipos diferentes. Nos modelos atuais, o raciocínio (módulo 2.4) fica sempre ligado, e a lista pode trazer um bloco de tipo `thinking` antes do texto. O texto do raciocínio vem vazio por padrão, mas os tokens dele são cobrados como saída. Por isso o laço da seção 4 confere o tipo antes de ler `bloco.text`. Nos próximos módulos aparecem outros tipos de bloco: pedidos de ferramenta e citações.

### 6. Instruções de sistema

As **instruções de sistema** são o equivalente às instruções de um Project (módulo 2.1): valem para a conversa inteira e ficam separadas das mensagens.

```python
resposta = cliente.messages.create(
    model=MODELO,
    max_tokens=16000,
    system="Você apoia analistas de CRM. Responda em até duas frases, em português do Brasil.",
    messages=[{"role": "user", "content": "O que é hard bounce?"}],
)
print(resposta.content[-1].text)
```

`resposta.content[-1]` é o último bloco da lista, que em uma resposta comum é o texto. Nos seus scripts, use a função `texto_da_resposta`, apresentada na seção 11.

O que você aprendeu sobre prompts nos níveis 1 e 2 vale aqui sem mudança: contexto, formato de saída, exemplos, documentos dentro de tags. A API só muda o lugar em que o texto é escrito.

### 7. A API não guarda a conversa

Cada chamada é independente. O modelo só conhece o que veio naquela requisição. Para continuar uma conversa, o script reenvia tudo: as mensagens anteriores e a nova.

```python
historico = [{"role": "user", "content": "A taxa de clique da campanha foi 2,4%. Em uma frase: como avaliar esse número?"}]

resposta = cliente.messages.create(model=MODELO, max_tokens=16000, messages=historico)
print(resposta.content[-1].text)

# A resposta entra no histórico, com o conteúdo inteiro, e depois vem a nova pergunta.
historico.append({"role": "assistant", "content": resposta.content})
historico.append({"role": "user", "content": "E qual seria o primeiro teste para melhorar?"})

resposta = cliente.messages.create(model=MODELO, max_tokens=16000, messages=historico)
print(resposta.content[-1].text)
print(resposta.usage.input_tokens)       # maior que na primeira chamada: o histórico foi cobrado de novo
```

Duas consequências:

- **O histórico é cobrado a cada chamada.** Na décima pergunta de uma conversa, você paga a entrada das nove anteriores outra vez. O módulo 3.5 mostra como o cache reduz esse custo.
- **Você controla a memória.** O script pode resumir, cortar ou começar do zero. No app, essa decisão não é sua.

Guarde `resposta.content` inteiro no histórico, e não só o texto. Os blocos de raciocínio fazem parte da resposta, e o modelo espera recebê-los de volta como foram gerados.

### 8. Esforço e motivos de parada

O **esforço** controla quanto o modelo raciocina antes de responder. É o mesmo controle do seletor do app (módulo 2.4), agora como parâmetro.

```python
resposta = cliente.messages.create(
    model=MODELO,
    max_tokens=16000,
    output_config={"effort": "low"},
    messages=[{"role": "user", "content": "Classifique o cargo 'Compradora Sênior' em uma palavra: Compras, Marketing ou Outros."}],
)
print(resposta.content[-1].text, resposta.usage.output_tokens)
```

Os valores são `low`, `medium`, `high`, `xhigh` e `max`. No Opus 5.5, o padrão é `medium`. Mais esforço gera mais tokens de saída e mais espera. Para tarefas simples e repetidas, como classificar um cargo, `low` costuma bastar. A decisão é tomada com medição, e não por palpite: você compara o acerto nos dois níveis contra um gabarito.

Antes de usar o conteúdo de uma resposta, confira o **motivo de parada**:

| `stop_reason` | Significado | O que o script faz |
| --- | --- | --- |
| `end_turn` | O modelo terminou | Usa a resposta |
| `max_tokens` | A resposta foi cortada pelo limite | Aumenta o limite ou divide a tarefa. A resposta cortada não é confiável |
| `refusal` | O pedido foi recusado pelos filtros de segurança | Registra e segue. O conteúdo pode vir vazio |
| `tool_use` | O modelo pediu uma ferramenta | Módulo 3.4 |
| `pause_turn` | Uma ferramenta que roda na Anthropic pausou a resposta | Módulo 3.4 |

Para ver um corte acontecer:

```python
resposta = cliente.messages.create(
    model=MODELO,
    max_tokens=40,
    messages=[{"role": "user", "content": "Explique em detalhes o que é uma régua de comunicação de feira."}],
)
if resposta.stop_reason == "max_tokens":
    print("Resposta cortada pelo limite de tokens.")
```

O raciocínio conta dentro do `max_tokens`. Com um limite muito baixo, o modelo pode gastar tudo raciocinando e não escrever nada.

### 9. Streaming

Em uma chamada comum, a resposta chega inteira, depois de pronta. Com **streaming**, ela chega em pedaços enquanto é gerada, como no app.

```python
with cliente.messages.stream(
    model=MODELO,
    max_tokens=64000,
    messages=[{"role": "user", "content": "Liste cinco assuntos de e-mail para convidar compradores a uma feira de embalagens."}],
) as fluxo:
    for trecho in fluxo.text_stream:
        print(trecho, end="", flush=True)
    print()
    final = fluxo.get_final_message()       # a resposta completa, com stop_reason e usage

print(final.stop_reason, final.usage.output_tokens)
```

O `with` é o mesmo que você usou para abrir arquivos: ele garante que a conexão é fechada ao fim do bloco.

Quando usar:

- Há uma pessoa esperando na tela. Ver o texto aparecer reduz a espera percebida.
- A resposta é longa. Conexões paradas por muitos minutos podem ser derrubadas no caminho. Com streaming, a conexão fica ativa, e por isso o limite de saída pode ser maior.

Para processar registros em um laço, sem ninguém olhando, a chamada comum é mais simples e basta.

### 10. O custo de uma chamada

O custo sai do campo `usage`:

```python
uso = resposta.usage
custo = (uso.input_tokens * 4.00 + uso.output_tokens * 20.00) / 1_000_000
print(f"Entrada {uso.input_tokens} | saída {uso.output_tokens} | custo US$ {custo:.5f}")
```

A saída custa cinco vezes a entrada. Em tarefas de classificação e extração, com respostas curtas, o peso está na entrada: instruções longas repetidas milhares de vezes. Em tarefas de redação, o peso está na saída.

Uma ordem de grandeza para guardar: mil chamadas com 500 tokens de entrada e 100 de saída custam, no Opus 5.5, `1000 × (500 × 4 + 100 × 20) / 1.000.000` = 4 dólares.

### 11. As funções de apoio do nível

Para não repetir os mesmos parâmetros em todo script, o nível usa um módulo de apoio, o [`claude_util.py`](gabarito/claude_util.py). Ele é material do curso, e não exercício: copie o arquivo do gabarito para a pasta `tratamento-bases` e leia o código.

| Função | O que faz |
| --- | --- |
| `criar_cliente()` | Cria o cliente |
| `chamar(cliente, mensagens, sistema, modelo, max_tokens, esforco, formato)` | Faz uma chamada com os padrões do curso e devolve a resposta |
| `texto_da_resposta(resposta)` | Junta os blocos de texto. Devolve `None` se o pedido foi recusado |
| `custo_em_dolares(uso, modelo, lote)` | Calcula o custo de uma chamada |
| `novo_total()`, `somar_uso(total, uso)` e `resumo_do_total(total)` | Acumulam tokens e custo de várias chamadas |

```python
import claude_util as cu

cliente = cu.criar_cliente()
resposta = cu.chamar(
    cliente,
    [{"role": "user", "content": "O que é soft bounce?"}],
    sistema="Responda em uma frase, em português do Brasil.",
    esforco="low",
)
print(cu.texto_da_resposta(resposta))
print(f"US$ {cu.custo_em_dolares(resposta.usage):.5f}")
```

A função `chamar` liga um recurso a mais: o **plano B para recusas**. Os modelos atuais têm filtros de segurança que podem recusar um pedido, às vezes por engano em um conteúdo legítimo. Com o parâmetro `fallbacks="default"`, a API refaz o pedido recusado em outro modelo, dentro da mesma chamada, e o seu script recebe a resposta normalmente. O recurso está em beta, por isso a chamada passa por `cliente.beta.messages.create` e leva um identificador de beta. O módulo 3.6 volta ao assunto.

### 12. O que sai do computador

Em cada chamada, sai do seu computador o que está em `system` e em `messages`, e nada além disso. O script não envia arquivos nem pastas por conta própria.

Isso torna a regra do módulo 1.5 mais fácil de cumprir e mais fácil de quebrar:

- Mais fácil de cumprir, porque você escolhe campo a campo o que entra na mensagem. Para classificar um cargo, basta enviar o cargo. Nome, e-mail e telefone ficam no computador.
- Mais fácil de quebrar, porque um laço envia a base inteira em segundos se você montar a mensagem com a linha completa.

Nos exercícios, os dados são fictícios. Com dados reais, vale o que você definiu no módulo 1.5: confirme a política da empresa e do cliente antes, e envie o mínimo necessário. Pelos termos comerciais da Anthropic, os dados enviados pela API não são usados para treinar modelos por padrão (referência: novembro de 2026).

## Exemplo aplicado

**Situação.** A equipe pergunta toda semana as mesmas coisas sobre o layout de importação: quais campos são obrigatórios, como vem o telefone, o que causa rejeição. Você quer um assistente de terminal que responda com base no layout.

**Decisões.**

1. O layout vai nas instruções de sistema, dentro de uma tag `<layout>`, como no módulo 2.2. Ele vale para a conversa toda.
2. As instruções pedem que o assistente diga quando a informação não está no layout. Sem isso, ele tende a completar com conhecimento geral.
3. A conversa usa histórico, para aceitar perguntas como "e um exemplo inválido?".
4. A resposta vem em streaming, porque há uma pessoa esperando.
5. Ao sair, o script mostra o total de tokens e o custo da conversa.

**As instruções de sistema.**

```python
from pathlib import Path


def montar_sistema(caminho_layout):
    layout = Path(caminho_layout).read_text(encoding="utf-8")
    return (
        "Você apoia analistas de CRM que preparam bases de contatos para importação. "
        "Responda com base no layout em <layout>. Se a pergunta não puder ser respondida "
        "com o layout, diga qual informação falta. Respostas curtas, em português do Brasil.\n\n"
        f"<layout>\n{layout}\n</layout>"
    )


print(montar_sistema("dados_n3/layout_importacao_crm.md")[:200])
```

**O que observar na conta.** O layout tem cerca de 1.700 caracteres e é enviado em toda chamada, junto com o histórico. Em uma conversa de dez perguntas, a entrada da décima chamada inclui o layout e as nove trocas anteriores. O resumo de custo ao fim da conversa mostra esse crescimento.

A solução completa está em [`gabarito/chat_terminal.py`](gabarito/chat_terminal.py).

## Erros comuns

- Colar a chave no código "só para testar". O teste vira commit.
- Rodar o `setx` e continuar no mesmo terminal. A variável só existe em terminais novos.
- Ler `resposta.content[0].text` sem conferir o tipo do bloco. O primeiro bloco pode ser de raciocínio.
- Guardar só o texto da resposta no histórico, em vez do conteúdo inteiro.
- Esquecer de acrescentar a resposta ao histórico e concluir que "o modelo esqueceu".
- Usar o conteúdo de uma resposta sem olhar o `stop_reason`.
- Definir um `max_tokens` baixo para "economizar". O limite não reduz o preço por token, só corta a resposta.
- Não definir limite de gasto no Console antes de rodar um laço.
