# 4.3 MCP

**Carga:** 5 h (2 h de leitura e experimentação, 3 h de exercício)

## Objetivo

Consultar um banco de dados com SQL, publicar os indicadores da campanha como um servidor MCP e usar o mesmo servidor no Claude Code, no app e nos seus agentes.

## Por que importa no seu trabalho

Até o módulo 4.2, as ferramentas viviam dentro de cada script. Se o assistente de perguntas, o agente de relatórios e o Claude Code precisam do mesmo indicador, cada um teria a sua cópia da função, e uma correção feita em um lugar não chegaria aos outros.

O **MCP** (Model Context Protocol) resolve isso. É um protocolo aberto, criado pela Anthropic e hoje usado por vários fornecedores, que define como um programa oferece ferramentas e dados a um modelo. Você escreve as ferramentas uma vez, em um **servidor MCP**, e qualquer aplicação que fale o protocolo passa a usá-las: o Claude Code, o Claude Desktop e os seus próprios agentes.

Os conectores que você usou no módulo 2.5 são servidores MCP mantidos por outras empresas. Neste módulo, você escreve o seu, sobre os dados da campanha.

Para isso, os dados vão para um banco SQLite, e as consultas são escritas em **SQL**, a linguagem padrão de consulta a bancos de dados. SQL é útil além deste módulo: muitas plataformas de CRM e de big data permitem exportar ou consultar dados com ela.

## Conteúdo

### 1. Por que um banco de dados

Até aqui, cada exportação era um CSV lido pelo pandas. Para um servidor que responde a muitas perguntas, um banco tem três vantagens:

| Vantagem | No seu trabalho |
| --- | --- |
| As tabelas ficam juntas e podem ser cruzadas | Disparos de WhatsApp com as tentativas de envio; e-mails de dois meses na mesma tabela |
| As consultas são curtas e reproduzíveis | "Envios de outubro por público" é uma frase de SQL |
| O acesso pode ser só de leitura | O servidor consulta, mas não consegue alterar nada |

O **SQLite** é um banco que fica em um único arquivo, sem instalação de servidor. O Python já traz o módulo `sqlite3` para usá-lo.

O script [`gabarito/montar_banco.py`](gabarito/montar_banco.py) lê as exportações da pasta `dados_n4` e cria o banco:

```bash
python montar_banco.py dados_n4 dados_n4/campanha.db
```

```

disparos_whatsapp: 3 linhas
whatsapp_tentativas: 1573 linhas
credenciados: 554 linhas
visitantes: 378 linhas
inscritos_evento: 56 linhas
```

| Tabela | Uma linha é | Colunas principais |
| --- | --- | --- |
| `disparos_email` | Um disparo de e-mail, de setembro ou outubro | `disparo`, `mes`, `data_envio`, `publico`, `enviadas`, `entregues`, `aberturas_unicas`, `cliques_unicos`, `descadastros` |

O banco é recriado a cada execução do script. Os CSV originais não mudam.

### 2. SQL mínimo

Os exemplos desta seção rodam em Python, com uma função que mostra o resultado de uma consulta:

```python
import sqlite3

import pandas as pd

conexao = sqlite3.connect("file:dados_n4/campanha.db?mode=ro", uri=True)


def ver(sql, parametros=()):
    print(pd.read_sql_query(sql, conexao, params=parametros).to_string(index=False))
```

O endereço `file:...?mode=ro` abre o banco **só para leitura** (*read-only*). Qualquer tentativa de alterar dados gera um erro.

#### Selecionar colunas: SELECT e FROM

```python
ver("SELECT disparo, publico, enviadas, entregues FROM disparos_email LIMIT 3")
```

```
                                          disparo        publico  enviadas  entregues
       2026_10_EXPOMODELO_Prospeccao_Faltam15Dias     Prospecção      8200       8110
2026_10_EXPOMODELO_Confirmacao_RespostaAutomatica         Outros         6          6
  2026_10_EXPOMODELO_Credenciamento_ConviteDireto Credenciamento      4000       3968
```

`SELECT` lista as colunas, `FROM` diz a tabela e `LIMIT` limita o número de linhas. As palavras do SQL costumam ser escritas em maiúsculas para separá-las dos nomes das colunas, mas isso é convenção: o banco aceita minúsculas.

#### Filtrar e ordenar: WHERE e ORDER BY

```python
ver("""
SELECT disparo, publico, enviadas
FROM disparos_email
WHERE mes = '2026-10' AND publico = 'Pré-credenciados'
ORDER BY enviadas DESC
""")
```

```
Empty DataFrame
Columns: [disparo, publico, enviadas]
Index: []
```

Nenhuma linha. O público se chama `Pré-credenciado`, no singular. Um filtro com um valor que não existe não gera erro: devolve um resultado vazio, que pode ser confundido com "não houve disparos". É o mesmo problema do zero que parece resposta (módulo 3.4), e é por isso que as ferramentas do servidor conferem os valores antes de consultar. Para ver os valores existentes de uma coluna, use `DISTINCT`:

```python
ver("SELECT DISTINCT publico FROM disparos_email ORDER BY publico")
```

```
        publico
 Credenciamento
      Expositor
         Outros
     Prospecção
Pré-credenciado
     Reativação
```

Com o valor certo:

```
                                         disparo         publico  enviadas
  2026_10_EXPOMODELO_PreCredenciado_Faltam10Dias Pré-credenciado      2250
2026_10_EXPOMODELO_PreCredenciado_ConvitePessoal Pré-credenciado      2100
```

`WHERE` filtra as linhas; condições se combinam com `AND` e `OR`. Textos vão entre aspas simples. `ORDER BY` ordena; `DESC` inverte a ordem, do maior para o menor.

#### Agrupar: GROUP BY, COUNT e SUM

```python
ver("""
SELECT mes, COUNT(*) AS disparos, SUM(enviadas) AS enviadas, SUM(entregues) AS entregues
FROM disparos_email
WHERE enviadas >= 10
GROUP BY mes
ORDER BY mes
""")
```

```
    mes  disparos  enviadas  entregues
2026-09        13     64307      62952
2026-10        14     50812      50116
```

`GROUP BY mes` junta as linhas de cada mês, e as funções de agregação calculam sobre cada grupo: `COUNT(*)` conta linhas, `SUM` soma, e há também `AVG` (média), `MIN` e `MAX`. `AS` dá nome à coluna calculada. O filtro `enviadas >= 10` aplica a regra do método do relatório: disparos com menos de 10 envios são respostas automáticas ou testes. Os números são os mesmos do módulo P.6.

#### Calcular taxas: o cuidado com a divisão

```python
ver("""
SELECT mes,
       SUM(aberturas_unicas) / SUM(entregues) AS divisao_inteira,
       ROUND(100.0 * SUM(aberturas_unicas) / SUM(entregues), 1) AS taxa_abertura
FROM disparos_email
WHERE enviadas >= 10
GROUP BY mes
""")
```

```
    mes  divisao_inteira  taxa_abertura
2026-09                0           45.7
2026-10                0           52.6
```

No SQLite, a divisão de dois números inteiros descarta as casas decimais: 26.385 dividido por 50.116 dá 0. Multiplicar por `100.0`, com ponto decimal, transforma a conta em decimal. `ROUND(valor, 1)` arredonda para uma casa.

#### Filtrar grupos: HAVING

```python
ver("""
SELECT publico, SUM(entregues) AS entregues,
       ROUND(100.0 * SUM(cliques_unicos) / SUM(entregues), 1) AS taxa_clique
FROM disparos_email
WHERE mes = ? AND enviadas >= ?
GROUP BY publico
HAVING SUM(entregues) >= 1000
ORDER BY taxa_clique DESC
""", ("2026-10", 10))
```

```
        publico  entregues  taxa_clique
Pré-credenciado       4248          3.7
 Credenciamento      16701          3.6
     Prospecção      26225          1.6
     Reativação       2780          1.0
```

`WHERE` filtra linhas antes de agrupar. `HAVING` filtra grupos depois. Aqui, públicos com menos de mil entregues ficam de fora: a taxa de clique do Expositor, com 162 entregues, não é comparável à dos outros (módulo 2.6).

Os pontos de interrogação são **parâmetros**, explicados adiante.

#### Cruzar tabelas: JOIN

As tentativas de WhatsApp têm o código do disparo, e o tema está em outra tabela. `JOIN` junta as duas pela coluna em comum:

```python
ver("""
SELECT d.disparo, d.tema, COUNT(*) AS tentativas, COUNT(DISTINCT t.telefone) AS contatos
FROM whatsapp_tentativas AS t
JOIN disparos_whatsapp AS d ON d.disparo = t.disparo
GROUP BY d.disparo, d.tema
ORDER BY d.disparo
""")
```

```
disparo                             tema  tentativas  contatos
     D1      Convite para credenciamento         526       456
     D2 Programação e rodada de negócios         517       456
     D3     Lembrete na véspera da feira         530       456
```

`AS t` e `AS d` são apelidos das tabelas, e `t.telefone` quer dizer "a coluna telefone da tabela t". `ON` diz como as linhas se correspondem. `COUNT(DISTINCT t.telefone)` conta telefones diferentes: cada contato pode ter mais de uma tentativa, e a entrega se mede em contatos (módulo P.7).

O `JOIN` mostrado é o **INNER JOIN**: só entram linhas que têm correspondência nas duas tabelas. Uma tentativa com um código de disparo que não está em `disparos_whatsapp` sumiria do resultado sem aviso. Quando isso importar, conte as linhas antes e depois do `JOIN`, ou use `LEFT JOIN`, que mantém todas as linhas da primeira tabela.

#### Parâmetros: nunca montar o SQL com o valor recebido

Quando o valor do filtro vem de fora (do usuário, ou do modelo, que pediu a ferramenta), ele entra como parâmetro, com `?` no SQL e o valor em separado. Compare:

```python
mes = "2026-10' OR '1'='1"     # um valor malicioso, ou só mal escrito

montado = pd.read_sql_query(f"SELECT * FROM disparos_email WHERE mes = '{mes}'", conexao)
com_parametro = pd.read_sql_query("SELECT * FROM disparos_email WHERE mes = ?", conexao, params=(mes,))
print(len(montado), len(com_parametro))
```

```
29 0
```

Na versão montada com o texto, o valor virou parte do comando, e a condição `OR '1'='1'` é sempre verdadeira: a consulta devolveu as 29 linhas da tabela, dos dois meses, em vez das 15 de outubro. Esse ataque se chama **injeção de SQL** (*SQL injection*). Com o parâmetro, o banco trata o valor como um texto a comparar, e o resultado é vazio, que é o correto: não existe um mês com esse nome.

Em uma ferramenta que o modelo chama, o pedido do modelo é uma entrada não confiável (módulo 3.4, regra 6). Parâmetros e conexão só de leitura são as duas garantias.

```python
conexao.execute("DELETE FROM disparos_email")
```

```
sqlite3.OperationalError: attempt to write a readonly database
```

#### Resumo do SQL deste módulo

| Cláusula | Para que serve | Exemplo |
| --- | --- | --- |
| `SELECT ... FROM` | Escolher colunas de uma tabela | `SELECT publico, enviadas FROM disparos_email` |
| `WHERE` | Filtrar linhas | `WHERE mes = ? AND enviadas >= 10` |
| `ORDER BY ... DESC` | Ordenar | `ORDER BY enviadas DESC` |
| `LIMIT` | Limitar linhas | `LIMIT 3` |
| `DISTINCT` | Valores diferentes | `SELECT DISTINCT publico` |
| `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` | Agregar | `SUM(entregues)` |
| `GROUP BY` | Agregar por grupo | `GROUP BY publico` |
| `HAVING` | Filtrar grupos | `HAVING SUM(entregues) >= 1000` |
| `JOIN ... ON` | Cruzar tabelas | `JOIN disparos_whatsapp AS d ON d.disparo = t.disparo` |
| `CASE WHEN ... THEN ... END` | Condição dentro de uma conta | `SUM(CASE WHEN status = 'erro' THEN 1 ELSE 0 END)` |
| `?` | Parâmetro | `WHERE mes = ?` |

O Claude escreve SQL bem. Use-o para escrever e explicar consultas, como fez com Python na Ponte. O que você precisa saber é ler a consulta e conferir o resultado contra um número conhecido.

### 3. Dos indicadores às ferramentas

O arquivo [`gabarito/indicadores.py`](gabarito/indicadores.py) guarda as consultas em funções, com as regras de desenho do módulo 3.4:

```python
def indicadores_email(mes):
    """Totais e taxas de e-mail de um mês, sem os disparos abaixo do mínimo de envios."""
    erro = conferir_mes(mes)
    if erro:
        return {"erro": erro}
    totais = consultar(
        """
        SELECT COUNT(*) AS disparos, SUM(enviadas) AS enviadas, SUM(entregues) AS entregues,

               SUM(descadastros) AS descadastros
        FROM disparos_email
        WHERE mes = ? AND enviadas >= ?
        """,
        (mes, MINIMO_DE_ENVIOS),
    ).iloc[0]
    ...
```

- `conferir_mes` recusa um mês fora do formato ou sem dados, com uma mensagem que lista os meses disponíveis. O resultado vazio do filtro errado nunca chega ao modelo.
- Toda consulta usa parâmetros e a conexão só de leitura.
- Nenhuma função devolve nome, e-mail ou telefone. O funil da feira usa as bases de pessoas para resolver a identidade (módulo P.7), mas devolve só contagens.
- A comparação com o mês anterior é uma função própria (`comparar_meses`), que calcula as diferenças em pontos percentuais. O modelo não faz contas.

As funções são Python comum e têm testes em `gabarito/test_nivel4.py`, que conferem os números com os da Ponte: em outubro, 50.812 envios, entrega de 98,6%, abertura de 52,6% e clique de 2,4%.

### 4. O servidor MCP

Um servidor MCP oferece três tipos de coisa a quem se conecta a ele:

| Tipo | O que é | Quem decide usar | No servidor da campanha |
| --- | --- | --- | --- |
| Ferramentas (*tools*) | Funções que o modelo chama | O modelo | Os sete indicadores |
| Recursos (*resources*) | Dados para leitura, identificados por um endereço | A aplicação ou o usuário | O dicionário dos indicadores, em `campanha://dicionario` |
| Prompts | Modelos de pedido prontos | O usuário | Nenhum |

O servidor de referência está em [`gabarito/servidor_campanha.py`](gabarito/servidor_campanha.py). Ele usa o pacote `mcp`, a biblioteca oficial do protocolo para Python (`pip install mcp`; o curso usa a versão 2.3, de novembro de 2026):

```python
from mcp.server.mcpserver import MCPServer

import indicadores as ind

servidor = MCPServer(
    "campanha-expo-modelo",
    instructions=(
        "Indicadores da campanha de marketing da Expo Modelo 2026: e-mail por mês e por público, "
        "WhatsApp por disparo e o funil da feira em pessoas. Os meses usam o formato AAAA-MM."
    ),
)


@servidor.tool()
def indicadores_email(mes: str) -> dict:
    """Totais e taxas de e-mail de um mês: disparos, enviadas, entregues, aberturas, cliques e as três taxas.

    Use para os indicadores gerais do relatório mensal. Disparos com menos de 10 envios ficam fora
    dos totais e aparecem em disparos_excluidos.

    Args:
        mes: Mês no formato AAAA-MM, como 2026-10.
    """
    return ind.indicadores_email(mes)


@servidor.resource("campanha://dicionario")
def dicionario() -> str:
    """Definições dos indicadores usados pelas ferramentas."""
    return "Taxa de entrega = entregues / enviadas. Taxa de abertura = aberturas únicas / entregues. ..."


if __name__ == "__main__":
    servidor.run()
```

O padrão é o mesmo do `@beta_tool` do módulo 3.4: o decorador `@servidor.tool()` transforma a função em ferramenta, a docstring vira a descrição e os tipos dos parâmetros viram o esquema de entrada. As `instructions` são lidas pelas aplicações que se conectam e ajudam o modelo a saber para que o servidor serve.

Em versões anteriores do pacote, a classe se chamava `FastMCP` e ficava em `mcp.server.fastmcp`. Exemplos antigos na internet usam esse nome.

`servidor.run()` inicia o servidor no transporte **stdio**: a aplicação que vai usar o servidor inicia o processo e conversa com ele pela entrada e saída padrão, como um programa de terminal. É o transporte dos servidores locais, que rodam no seu computador. O outro transporte, **HTTP**, serve para servidores remotos, publicados na internet (seção 8).

Você não roda o servidor sozinho no terminal: ele ficaria parado, esperando mensagens. Quem o inicia é a aplicação.

### 6. Usar no Claude Code

No Claude Code, um servidor local é cadastrado com `claude mcp add`. Na pasta do projeto, com o ambiente virtual ativado:

```bash
claude mcp add campanha -e BANCO_CAMPANHA=C:/curso/nivel4/dados_n4/campanha.db -- python C:/curso/nivel4/servidor_campanha.py
```

| Parte | O que é |
| --- | --- |
| `campanha` | O nome do servidor no Claude Code |
| `-e CHAVE=valor` | Variável de ambiente passada ao servidor |
| `--` | Separa as opções do Claude Code do comando que inicia o servidor |
| `python C:/curso/...` | O comando que inicia o servidor, com caminhos completos |

Troque os caminhos pelos da sua pasta. No Windows, barras normais (`/`) funcionam nos caminhos e evitam problemas com a barra invertida.

O cadastro tem três escopos, escolhidos com `-s`:

| Escopo | Onde fica | Quem usa |
| --- | --- | --- |
| `local` (padrão) | Na sua configuração, para esta pasta | Só você, só neste projeto |
| `project` | No arquivo `.mcp.json` do projeto, que vai para o Git | Quem clonar o repositório, depois de aprovar o servidor |
| `user` | Na sua configuração geral | Só você, em todos os projetos |

Para os dados da campanha, use `local`: o caminho do banco é do seu computador. Confira o cadastro com `claude mcp list`, que inicia o servidor e mostra se a conexão funcionou:

```
campanha: python C:/curso/nivel4/servidor_campanha.py - √ Connected
```

Dentro de uma sessão do Claude Code, o comando `/mcp` mostra os servidores e as ferramentas de cada um. A partir daí, perguntas sobre a campanha usam as ferramentas, e cada chamada pede a sua permissão, como qualquer ferramenta (módulo 4.4). As ferramentas aparecem com o nome `mcp__campanha__indicadores_email`: prefixo, nome do servidor e nome da ferramenta.

O cadastro e a verificação da conexão foram testados no ambiente de escrita do curso, em novembro de 2026.

### 7. Usar no app (Claude Desktop)

No app, servidores locais funcionam só no **Claude Desktop**, o aplicativo instalado no computador. O claude.ai no navegador e o app de celular não iniciam programas no seu computador.

O cadastro é feito em um arquivo de configuração. No Claude Desktop, abra **Settings > Developer > Edit Config**. O arquivo `claude_desktop_config.json` abre no editor. Acrescente o bloco `mcpServers`:

```json
{
  "mcpServers": {
    "campanha": {
      "command": "C:/curso/nivel4/.venv/Scripts/python.exe",
      "args": ["C:/curso/nivel4/servidor_campanha.py"],
      "env": {"BANCO_CAMPANHA": "C:/curso/nivel4/dados_n4/campanha.db"}
    }
  }
}
```

Três cuidados:

1. **Caminhos completos.** O Claude Desktop não inicia o servidor na pasta do projeto, e não ativa o ambiente virtual. Por isso o comando aponta para o Python de dentro do `.venv`, onde o pacote `mcp` foi instalado. No macOS, esse caminho é `.venv/bin/python`.
2. **Reinicie o app** depois de salvar o arquivo. A configuração é lida na abertura.
3. **Se o servidor não aparecer**, o Claude Desktop guarda registros de erro (*logs*) dos servidores MCP. Os erros mais comuns são caminho errado, JSON inválido (uma vírgula a mais ou a menos) e pacote não instalado no Python apontado.

O arquivo fica em `%APPDATA%\Claude\` no Windows e em `~/Library/Application Support/Claude/` no macOS. Administradores de organizações podem desligar os servidores locais; se a opção **Developer** não aparecer, essa é uma causa possível.

Esta seção foi escrita a partir da documentação oficial de novembro de 2026 e não pôde ser testada no ambiente de escrita do curso, que não tem o Claude Desktop. Os nomes dos menus mudam com as versões do app: se algum passo não bater, procure "MCP" ou "Developer" nas configurações.

### 8. Servidores remotos e conectores personalizados

O claude.ai no navegador e o Cowork na nuvem usam **conectores personalizados** (*custom connectors*): servidores MCP remotos, que a Anthropic acessa pela internet. Em planos individuais, o caminho é **Customize > Connectors > Add custom connector**; em planos Team e Enterprise, um administrador cadastra em **Organization settings > Connectors**.

Um servidor remoto tem exigências que o local não tem:

| Exigência | Por quê |
| --- | --- |
| Endereço público, em HTTPS na porta 443 | A conexão parte da nuvem da Anthropic, e não do seu computador. Servidor atrás de VPN ou firewall não é alcançado |
| Autenticação | Qualquer pessoa na internet pode tentar se conectar. O padrão é OAuth, o "entrar com a sua conta" que você usa em outros sites; também há chaves enviadas em cabeçalhos |
| Hospedagem | O servidor fica ligado em algum serviço de nuvem, com custo e manutenção |

Para os dados da campanha, que vêm de bases com dados pessoais, o servidor local é a escolha deste módulo: os dados não saem do computador, e só os resultados agregados vão para o modelo. Publicar um servidor remoto é tema do Nível 5, quando o agente de relatórios for entregue a outras pessoas.

Informações de novembro de 2026, da central de ajuda da Anthropic.

### 9. Usar no seu agente

O mesmo servidor serve aos seus scripts. O SDK da Anthropic tem uma ponte que transforma as ferramentas de uma sessão MCP em ferramentas do executor:

```python
from anthropic.lib.tools.mcp import async_mcp_tool

async with stdio_client(SERVIDOR) as (leitura, escrita):
    async with ClientSession(leitura, escrita) as sessao:
        await sessao.initialize()
        ferramentas = [async_mcp_tool(t, sessao) for t in (await sessao.list_tools()).tools]
        executor = cliente.beta.messages.tool_runner(
            model=cu.MODELO, max_tokens=16000, system=SISTEMA, tools=ferramentas,
            messages=[{"role": "user", "content": pergunta}], output_config={"effort": "low"},
            max_iterations=8, thread=False, **cu.opcoes_de_fallback(),
        )
        async for mensagem in executor:
            ...
```

O assistente completo está em [`gabarito/agente_mcp.py`](gabarito/agente_mcp.py). O cliente da API é o `anthropic.AsyncAnthropic()`, a versão assíncrona, porque a sessão MCP também é. O agente de relatórios do projeto usa o mesmo arranjo, com ferramentas do servidor e ferramentas próprias juntas.

A ligação entre o servidor e o executor foi testada no servidor simulado da API; a chamada ao modelo real não foi executada no ambiente de escrita.

### 10. Segurança de servidores MCP

Um servidor MCP local é um programa que roda com as suas permissões, no seu computador. As regras:

| Regra | Por quê |
| --- | --- |
| Instale servidores de terceiros só de fontes confiáveis | Instalar um servidor é instalar um programa. Ele pode ler os seus arquivos |
| Leia as ferramentas que um servidor oferece antes de usar | A descrição de uma ferramenta entra no contexto do modelo e pode conter instruções escondidas (injeção, módulo 2.5) |
| Nos seus servidores, só leitura e só agregados | O modelo, ou um texto malicioso lido por ele, não consegue alterar dados nem extrair contatos |
| Credenciais por variável de ambiente, nunca no código | O código vai para o Git; a variável fica no seu computador |
| Ferramentas que agem fora do computador exigem aprovação | O Claude Code pede permissão a cada chamada; nos seus agentes, a aprovação é sua responsabilidade (módulo 4.1) |

## Exemplo aplicado

**Situação.** Na revisão do relatório de outubro, a coordenação pergunta: "a abertura subiu em relação a setembro? E o volume?". Em vez de abrir as planilhas, você pergunta ao Claude Code, com o servidor da campanha cadastrado.

**O caminho.**

1. O Claude Code lê a pergunta e escolhe a ferramenta `mcp__campanha__comparar_meses`, com `mes_atual="2026-10"` e `mes_anterior="2026-09"`. Você aprova a chamada.
2. O servidor consulta o banco e devolve:

   ```
   "atual":    {"enviadas": 50812, "taxa_entrega": 98.6, "taxa_abertura": 52.6, "taxa_clique": 2.4}
   "anterior": {"enviadas": 64307, "taxa_entrega": 97.9, "taxa_abertura": 45.7, "taxa_clique": 1.8}
   "diferencas_pp": {"taxa_entrega": 0.7, "taxa_abertura": 6.9, "taxa_clique": 0.6, "variacao_enviadas_pct": -21.0}
   ```

3. A resposta usa esses números: a abertura subiu 6,9 pontos percentuais, de 45,7% para 52,6%, com 21% menos envios.

**O que conferir.** Os números da resposta devem ser exatamente os da ferramenta. O Claude Code mostra a chamada e o resultado, e a conferência leva segundos. Se a resposta trouxer um número que não está no resultado, como uma projeção para novembro, ele não veio do banco.

**O que não aconteceu.** Nenhuma linha de contato saiu do computador. A ferramenta devolve totais, e o banco foi aberto só para leitura.

Os números do resultado vêm da execução real do servidor sobre os dados fictícios do curso.

## Erros comuns

- Filtrar com um valor escrito de outro jeito e ler o resultado vazio como "não houve".
- Dividir dois inteiros no SQLite e obter zero.
- Usar `WHERE` para filtrar um resultado agregado, que pede `HAVING`.
- Fazer `JOIN` sem conferir se linhas sumiram por falta de correspondência.
- Montar o SQL com o valor recebido, em vez de usar parâmetros.
- Abrir o banco com permissão de escrita em um servidor que só precisa ler.
- Devolver linhas de contatos em uma ferramenta, em vez de contagens.
- Rodar o servidor sozinho no terminal e achar que ele travou. Quem o inicia é a aplicação.
- Usar caminhos relativos ou o Python fora do ambiente virtual na configuração do Claude Desktop.
- Gravar credenciais no código do servidor ou no `.mcp.json` que vai para o Git.
- Instalar servidores MCP de terceiros sem ler o que eles fazem.

## Checagem rápida

1. Que problema o MCP resolve?
2. Quais são os três tipos de coisa que um servidor MCP oferece, e quem decide usar cada um?
3. Qual é a diferença entre `WHERE` e `HAVING`?
4. Por que `SUM(aberturas_unicas) / SUM(entregues)` dá zero no SQLite, e como corrigir?
5. O que é injeção de SQL, e quais são as duas garantias contra ela neste módulo?
6. Qual é a diferença entre os transportes stdio e HTTP?
7. Por que o servidor da campanha não pode ser usado no claude.ai pelo navegador?
8. Em que escopo você cadastra no Claude Code um servidor que aponta para um arquivo do seu computador, e por quê?

<details>
<summary>Respostas</summary>

1. As ferramentas passam a ser escritas uma vez, em um servidor, e usadas por qualquer aplicação que fale o protocolo, em vez de copiadas em cada script.
2. Ferramentas, que o modelo decide chamar; recursos, que a aplicação ou o usuário escolhe ler; e prompts, que o usuário escolhe usar.
3. `WHERE` filtra linhas antes do agrupamento; `HAVING` filtra grupos depois dele.
4. Porque a divisão de dois inteiros descarta as casas decimais. Multiplicar por `100.0` antes de dividir torna a conta decimal.
5. É quando um valor recebido de fora vira parte do comando SQL e muda o que a consulta faz. As garantias são os parâmetros (`?`) e a conexão só de leitura.
6. No stdio, a aplicação inicia o servidor no mesmo computador e conversa pela entrada e saída padrão. No HTTP, o servidor fica publicado em um endereço e é acessado pela rede.
7. Porque é um servidor local, em stdio. O claude.ai acessa servidores remotos, a partir da nuvem da Anthropic, e não inicia programas no seu computador.
8. No escopo `local`, porque o caminho do banco só existe no seu computador e o cadastro não deve ir para o repositório.
